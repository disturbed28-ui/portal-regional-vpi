# Decisões técnicas do projeto

- **Cadastro de eventos na agenda via flyer/texto:** o fluxo vive em `src/components/agenda/AdicionarEventoDialog.tsx` + edge functions `interpretar-flyer` (IA extrai campos) e `agenda-criar-evento` (grava no Google Agenda via connector gateway). A escolha da agenda de destino (regional vs. times especiais) lê `agenda_calendars` por nome ("Elite"/"Regional") — nunca fixar IDs de calendário no código. Autoria registrada em `evento_autoria` para edição/exclusão futura pelo autor. Permissão controlada pela matriz (`/agenda/adicionar-evento`), validada no backend via `user_has_screen_permission`.
- **Flyers de eventos:** bucket privado `agenda-flyers` (workspace bloqueia buckets públicos); o link na descrição do evento usa URL assinada de 1 ano.
- **Links curtos de flyer:** a descrição do evento usa `https://vp1.app.br/flyer/<code>` (tabela `agenda_flyers`, rota React `/flyer/:code` → edge function pública `flyer` com verify_jwt=false, que assina a URL na hora). Nunca voltar a embutir URL assinada longa na descrição — o link curto não expira e funciona em convites de WhatsApp.
- **PD – Processo Disciplinar:** página `src/pages/ProcessoDisciplinar.tsx` + `src/components/pd/`. Toda transição de status (emitir, abrir, versão regional, encaminhar, devolutiva, concluir, cancelar) passa pela função `pd_acao` no banco, que valida permissão, gera o número anual com lock e grava a linha do tempo — o app só edita direto o próprio rascunho. Assim o original fica imutável e a numeração não tem buracos. Quem trata = matriz `/formularios/processo-disciplinar/regional` + escopo por grau (`pd_pode_tratar`).
- PD regional summaries are generated by the authenticated `pd-gerar-versao` function from server-read originals, then saved through `pd_acao`; WhatsApp uses the persisted regional fields and server-recorded signer identity to prevent sending unsaved or original content.
- Agenda sync only marks a DB event as removed when get-calendar-events reports a complete read, the event date is inside the returned window, and it was not hidden by visibility rules — partial reads previously archived real attendance lists.
- **Frequência ponderada:** o peso de cada tipo vem de `tipos_evento_peso` e é resolvido no banco pelo gatilho `eventos_set_tipo_peso` (preenche `eventos_agenda.tipo_evento_peso` a partir de `tipo_evento`), então qualquer caminho que grave um evento já sai com peso — o app não deve calcular isso. A leitura no app passa por `src/lib/frequenciaEventos.ts` (`pesoDoEvento`/`numeroOuPadrao`), porque o PostgREST devolve `numeric` como texto e somar texto vira concatenação; tipos sem linha na tabela valem 1 e Combate é excluído por esse mesmo arquivo.
- **Planilha de estrutura:** edge function `sync-estrutura-sheets` reescreve abas Comandos/Regionais/Divisoes/Info no Google Sheets (connector gateway); ID da planilha em `system_settings.google_sheets_estrutura_id`; cron diário + botão em Admin Estrutura. A planilha é espelho do portal — nunca editar nela, é sobrescrita.
- **Divisões novas na carga de integrantes:** antes de confirmar, `TelaConferenciaImport` usa `src/lib/estruturaNovasDivisoes.ts` para criar divisões (e regionais, quando o comando é conhecido) que não existem; sem regional identificável abre `ModalNovasDivisoes`. Gatilhos por comando em comandos/regionais/divisoes chamam `sync-estrutura-sheets` via pg_net para manter a planilha em dia.
- Public surveys mount outside the authenticated provider subtree and use credential-free browser requests to a fixed-sheet edge endpoint; only validated anonymous appends are permitted, preserving sheet headers and preventing session-linked access logging.
- **Relatório da Pesquisa de Satisfação:** aba em Relatórios (`PesquisaSatisfacaoTab`) lê só pela edge function autenticada `pesquisa-satisfacao-relatorio`, que deriva o escopo (grau/papéis/perfil) no servidor, lê a planilha de respostas e guarda as análises de IA em `pesquisa_analises` (sem acesso do navegador), regeneradas em segundo plano só quando o hash das respostas autorizadas muda. Períodos só em meses inteiros e mínimo de respostas por divisão (`system_settings.pesquisa_min_respostas_qualitativo`) protegem o anonimato; o formulário público não é tocado.
- Survey participation denominators come from paginated active-member scope-ID reads in the authenticated report endpoint; compare anonymous response counts with current membership, never identify respondents or infer unique-person coverage.
- CMD forms, summaries and exports share the movement readers and manual-first event merge in `supabase/functions/_shared`; saved dated movements are filtered by their actual month, and regional effective totals exclude internal transfers and suspension lifecycle events while division details preserve them, preventing duplicate or out-of-month growth records.
- Movement history reads paginated creation, load, manual audit, resolved delta and suspension events through `useHistoricoMovimentacoesCompleto`; reconstruct event-time locations instead of filtering only currently active members, so past entries, exits and transfers remain visible without changing access permissions.
